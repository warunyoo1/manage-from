# Manage From

Next.js App Router + TypeScript + Tailwind CSS สำหรับจัดการรายการเบิกจ่ายแยกตามสถานะ ใช้ไฟล์ `nextjs-fullstack-vercel-free.md` เป็นแนวทางด้านสถาปัตยกรรม

## หน้าจอปัจจุบัน

- `/` แสดงการ์ดสถานะ 4 ใบ: จ่าย / ค้างจ่าย / หน้างานถูกชะลอ / ตรวจสอบเพิ่มเติม พร้อมจำนวนรายการและยอดรวม ไม่มีแท็บและไม่มีการ์ดแยกเจ้าหนี้
- `/status/[status]` ตารางรวมรายการของทุกเจ้าหนี้และทุกโปรเจกต์ที่ตรงกับสถานะของการ์ดนั้น ค้นหาและกรองเจ้าหนี้ร่วมกับโปรเจกต์ได้ เปลี่ยนสถานะแล้วรายการย้ายไปการ์ดใหม่ทันที
- ช่องสถานะใช้เมนูป้ายสี และเลือกสถานะได้เมื่อเพิ่มรายการด้วย ยอดยังไม่ชำระรวมรายการค้างจ่าย ชะลอ และรอตรวจสอบ จะแสดงวันที่ชำระเฉพาะสถานะจ่าย โดยข้อมูลเดิมที่บันทึกเป็น `จ่ายแล้ว` ยังคงอ่านได้
- หน้ารวมและตารางใช้โทนเขียวอมฟ้าของ Manage From การ์ดพื้นขาว พร้อมสีประจำแต่ละสถานะและภาพรวมยอดเงิน
- `/creditors/[id]` ตาราง 16 คอลัมน์ตามภาพอ้างอิง แสดงเฉพาะเจ้าหนี้ที่เลือกจากทุกโปรเจกต์ พร้อมยอดรวม จ่ายแล้ว และค้างจ่าย
- ยอดสรุปบนหน้าสถานะรวมทุกรายการในสถานะนั้น ส่วนยอดท้ายตารางรวมเฉพาะแถวที่ตรงกับคำค้นหาและตัวกรอง
- เพิ่มรายการโดยเลือกเจ้าหนี้ แล้วเลือกโปรเจกต์เดิมหรือเพิ่มโปรเจกต์ใหม่ สถานะเริ่มต้นตามการ์ดที่เปิด และเพิ่มเจ้าหนี้ใหม่ได้จากหน้าหลัก
- ลิงก์ `/projects/[id]` เดิมจะกลับไปหน้ารวมสถานะ
- ค้นหา กรองสถานะ เพิ่มรายการ เปลี่ยนสถานะจ่าย วันที่ชำระ ติ๊กลง Flow และส่งออก CSV ของรายการที่กรองไว้

ข้อมูลใช้งานอ่านและบันทึกผ่าน `/api/workspace` ลง MongoDB ฐานข้อมูล `manage_from` (เปลี่ยนด้วย `MONGODB_DB`) ข้อมูลถูกแชร์ระหว่างเบราว์เซอร์ที่เปิดแอปเดียวกัน การติ๊กลง Flow ยังเป็นเพียงสถานะในแอป ไม่ได้เชื่อมบริการ Flow ภายนอก

ระบบเริ่มจากฐานข้อมูลว่างสำหรับทดสอบข้อมูลจริง ไม่อ่านหรือนำเข้าข้อมูลเดิมจาก localStorage และไม่มีคำสั่งนำเข้าผ่าน API ข้อมูลตัวอย่างเก่าใช้เฉพาะในการตรวจสอบ ไม่เติมลงฐานข้อมูลใช้งาน

แต่ละรายการเชื่อม `creditorId` และ `projectId` พร้อมรายละเอียดงาน แผนงวดและรหัสชุดงาน การบันทึกเจ้าหนี้ หน้างาน และรายการใหม่เกิดพร้อมกันในเอกสาร workspace หนึ่งใบ โดยตรวจ revision ก่อนเขียนเพื่อป้องกันการเขียนทับจากหลายหน้า หากข้อมูลเปลี่ยนจากอีกหน้า ระบบโหลดข้อมูลล่าสุดและแจ้งให้ลองบันทึกอีกครั้ง ฟอร์มจะไม่ปิดเมื่อบันทึกไม่สำเร็จ

API ตรวจข้อมูล ความสัมพันธ์ งวดซ้ำ และยอดสุทธิก่อนบันทึก และไม่ส่งรายละเอียดการเชื่อมต่อหรือข้อผิดพลาดจากไดรเวอร์กลับไปที่เบราว์เซอร์

พรีวิวในแอปยังไม่รายงานการดาวน์โหลดไฟล์ CSV จึงยังไม่ได้ยืนยันขั้นตอนดาวน์โหลดผ่านพรีวิวนี้

## เริ่มใช้งาน

ใช้ Node.js 20.9 ขึ้นไป

```bash
npm install
npm run dev
```

เปิด http://localhost:3000

## โครงสร้าง

```text
app/                  หน้าเว็บและ API ในโปรเจกต์เดียวกัน
  api/health/         GET /api/health สำหรับตรวจว่าแอปตอบสนอง
  api/workspace/      GET / POST ข้อมูลใช้งานผ่าน MongoDB
lib/workspace-actions.ts    ตรวจข้อมูลและความสัมพันธ์ก่อนบันทึก
lib/workspace-repository.ts อ่านและเขียน workspace แบบตรวจ revision
lib/workspace-store.ts      ฝั่งเบราว์เซอร์เรียก API และสถานะการบันทึก
components/ui/        ส่วนประกอบหน้าจอที่ใช้ซ้ำ
lib/db.ts             ตัวเชื่อมต่อ MongoDB พร้อม cache และ retry เมื่อเชื่อมต่อล้มเหลว
lib/validations/      พื้นที่สำหรับตรวจสอบข้อมูลก่อนใช้งาน
models/               พื้นที่สำหรับ Mongoose models
services/             พื้นที่สำหรับ business logic
types/                ชนิดข้อมูลร่วมกัน
```

หน้ารายการต้องเชื่อม MongoDB ได้ หากเชื่อมต่อไม่ได้จะแสดงข้อความและปุ่มลองอีกครั้ง ส่วน `/api/health` ตรวจการตอบสนองของแอปเท่านั้น ไม่ได้ทดสอบฐานข้อมูล

ตั้งค่า `.env.local` จาก `.env.example`: ใส่ `MONGODB_URI` และ `MONGODB_DB=manage_from` ตัวเชื่อมต่อเรียกเฉพาะฝั่งเซิร์ฟเวอร์ ห้ามใช้ชื่อตัวแปร `NEXT_PUBLIC_` กับข้อมูลเชื่อมต่อ และห้าม commit `.env.local`

## ขั้นตอนถัดไป

กำหนดกลุ่มผู้ใช้ บทบาท ขั้นตอนการทำงาน และข้อมูลที่ต้องจัดเก็บรวมถึงการยืนยันตัวตนและสิทธิ์ก่อนเปิดระบบให้ผู้ใช้ภายนอก และเลือกรูปแบบ Auth.js และผู้ให้บริการเข้าสู่ระบบเมื่อทราบความต้องการแล้ว

## Vercel

โครงนี้ใช้ Next.js ในโปรเจกต์เดียว สามารถนำ repository ไป import ใน Vercel และตั้งค่าตัวแปร `MONGODB_URI` และ `MONGODB_DB` ยังไม่ได้สร้าง deployment หรือเชื่อมบัญชีบริการภายนอก

## Inspo MCP

ตั้งค่า hosted endpoint `https://inspomcp.dev/api/mcp` ให้ Codex, Cursor และ VS Code แล้ว ต้องเปิด client ใหม่เพื่อให้โหลดการเชื่อมต่อ การติดตั้งนี้อยู่ในค่าของเครื่อง ไม่ใช่ dependency ของแอป

## สถานะ dependencies ตอนเริ่มต้น

`npm audit` แจ้ง 5 รายการระดับ high ใน dependency chain ของเครื่องมือ ESLint (`braces` → `micromatch` → `fast-glob` → Next ESLint plugin/config) โดยคำแนะนำอัตโนมัติให้ downgrade config ข้าม major จึงยังไม่ได้ใช้ `--force` ควรตรวจอีกครั้งเมื่อมีเวอร์ชันแก้ไข ส่วน `npm audit --omit=dev` ไม่พบช่องโหว่ใน production dependencies ณ วันที่สร้างโครง

- ฟอร์มเพิ่ม/แก้ไขเป็นเอกสารแนวนอนตามภาพอ้างอิง คลิกเส้นใต้เพื่อแก้ไขชื่อหน้างาน ผู้รับจ้าง ข้อมูลติดต่อ หมวดงาน รายละเอียด งวดเบิก บัญชีธนาคาร ผู้ตั้งเบิก และผู้อนุมัติ พิมพ์ชื่อหน้างานหรือผู้รับจ้างใหม่เพื่อเพิ่มพร้อมรายการในครั้งเดียว
- คำนวณยอดรับเงินจากจำนวนเงินที่ขอเบิก VAT และอัตราหักที่ผู้ใช้เลือก มูลค่าในตารางและการ์ดคือยอดรับเงินสุทธิ ตัวอย่าง 6,200 / เบิก 3,100 / หัก 3% ได้ 3,007 บาท ยอดคงเหลือหักยอดเบิกก่อนหน้าและยอดขอเบิกปัจจุบันจากมูลค่างาน
- กด “แก้ไขเอกสาร” ในช่องลักษณะงานของตารางเพื่อเปิดเอกสารเดิม การเปิดแถวเก่าที่ยังไม่มีเอกสารจะคงยอดเดิมและไม่เพิ่มภาษีหักอัตโนมัติ ช่องเพิ่มเติมสำหรับยอดเบิกก่อนหน้า วันชำระ หมายเหตุ และ Flow อยู่ด้านล่างเอกสาร
- เพิ่มแผนงวดในเอกสารได้ด้วยปุ่ม “เพิ่มงวด” กำหนดยอดและวันที่ของแต่ละงวด แล้วเลือกขอเบิกทีละงวด การบันทึกสร้างเฉพาะงวดที่เลือกและเก็บแผนไว้ในเอกสาร เปิดรายการเดิมเพื่อเบิกงวดถัดไปได้ งวดที่บันทึกแล้วจะแก้รายการเดิมแทนการสร้างซ้ำ ยอดคงเหลือหักเฉพาะงวดที่บันทึกแล้วและงวดปัจจุบัน ส่วนยอดรวมตามแผนแสดงแยกเพื่อป้องกันแบ่งยอดเกินมูลค่างาน
- หน้าต่างเอกสารซ่อนแถบเลื่อนและล็อกการเลื่อนหน้าด้านหลัง ยังคงเลื่อนภายในเอกสารด้วยเมาส์ สัมผัส หรือแป้นพิมพ์ได้
- การเบิกต่อเลือกเจ้าหนี้ → หน้างาน → หมวดงาน → การ์ดชุดงาน ระบบเลือกงวดแรกที่ยังไม่ได้ขอเบิกและใช้แผนเดิมต่อ แต่ละชุดงานใช้รหัสเฉพาะ จึงแยกแผนที่มีชื่อหมวดงานเหมือนกันได้ เอกสารในชุดงานเดิมล็อกเจ้าหนี้ หน้างาน และหมวดงาน หากต้องการงานใหม่ให้กดเริ่มชุดงานใหม่ ระบบตรวจความสัมพันธ์และงวดซ้ำก่อนบันทึก
- หน้าเพิ่มรายการเริ่มด้วยสองทางเลือก “สร้างงานใหม่” และ “เบิกงวดถัดไป” งานเดิมแสดงตัวเลือกตามลำดับและเลือกหน้างาน/หมวดงานให้เมื่อมีเพียงตัวเลือกเดียว แสดงชุดงานเป็นการ์ดพร้อมปุ่มเบิกงวดที่ระบุ เปิดหน้าสรุปให้แก้วันที่และยอดของงวดปัจจุบันก่อนบันทึก เอกสารฉบับเต็มเปิดดูหรือแก้ไขได้ในส่วนพับด้านล่าง ส่วนงานใหม่ยังใช้ฟอร์มเอกสารตามภาพอ้างอิง


## ทดสอบข้อมูล

`npm run test:status` ตรวจสถานะ ยอดเอกสาร แผนงวด และความสัมพันธ์ ส่วน `npm run test:db` ทดสอบกับฐานข้อมูลที่ตั้งค่าไว้โดยใช้ข้อมูลสมมติในเอกสารทดสอบที่มีรหัสเฉพาะ ตรวจการบันทึก/อ่านกลับ การป้องกันเขียนทับ และการปิดใช้งานคำสั่งนำเข้าข้อมูลเดิม แล้วลบเฉพาะเอกสารทดสอบที่สร้าง ไม่แก้ข้อมูลใช้งาน `main`
